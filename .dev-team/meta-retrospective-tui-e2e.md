# Meta Retrospective — TUI 重建安装与端到端验证（2026-10-18）

## 1. 通信拓扑与信噪比
- Roster：Lead + executor + test-agent（3 人），无冗余参谋；审查由 Lead 兼任裁决，未派生 L3 池。
- 消息总数 6 条，全部为任务派发/裁决/汇报，无套话；汇报均 ≤15 行，符合零废话要求。
- 缺陷：executor 曾误报"修复被外部覆盖"（实际文件在位，仅 git status 未显示），产生 1 轮无效往返；根因是核对方式（status 而非 grep 源码内容）。

## 2. 门禁穿透与误杀率
- 红相先行有效：test-agent 冻结套件先红（8/9），T2c 真实拦截了终端恢复缺陷。
- 误杀 1 次 + 漏判 1 次，均由测试自身缺陷造成，而非被测实现：
  - 误杀：T2c 首版用 `kill -INT script`，pty master 外部销毁，进程内不可能落盘 1049l → 判 TEST-DEFECT，改注入为直发 pony 进程 SIGHUP。
  - 漏判（关键）：套件优先选 `target/debug/pony-tui` 陈旧二进制（10-10），导致修复后仍显示失败；改正二进制解析（mtime 新于源码的 `pony`）后 11/11 绿。
- 教训：验收套件必须机械绑定"本次构建产物"，用 mtime/路径校验，禁止按名字猜二进制。

## 3. 分工契约与隔离有效性
- 写域正交：executor 仅改 `crates/pony-agent-core/src/bin/tui.rs`；test-agent 仅改 `tests/acceptance/**`；Lead 未写业务码，仅做诊断性只读复跑（/tmp 副本）。
- 测试冻结（chmod 444）在修复期间生效，修复者全程未触碰用例；豁免修正仅由 test-agent 执行，符合分权底线。
- 并行开销可忽略（2 人），但串行依赖强：修复 → 冻结重跑；未出现写冲突。

## 4. 元协议迭代建议（对 dev-team skill）
1. 验收套件"被测对象绑定"应升为强制项：测试必须在断言前校验二进制路径与源码 mtime/哈希，并把绑定信息写入收据；否则易出现测旧产物导致的假红/假绿。
2. 信号类 E2E 用例应显式声明注入目标（进程 pid vs 包装器 pid），并在 skill 中给出"包装器先销毁 pty 不可补救"的判定范例，避免重复误杀。
3. 汇报中"事实核对方式"应要求附命令：任何"文件被覆盖/丢失"的断言必须附 `grep path:line` 证据，禁止仅凭 `git status` 下结论。
