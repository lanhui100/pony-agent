# Wave-36 元复盘（PA-138..PA-145）

## 1. 通信拓扑与信噪比

- 45 条 C-id 契约矩阵一次冻结，跨 3 类角色（protocol/test/executor）零重复澄清；严苛 JSON/收据协议执行良好。
- 失效点：常驻 teammate（test-agent/executor-a/executor-b）共 6+ 次轮次崩溃（无 closing message），每 次
  浪费 5-15 分钟状态考古。结论：该环境下长上下文常驻 teammate 不稳定，**默认编排应为「无状态 subagent 池 +
  Lead 账本」，teammate 仅用于需要跨多轮谈判的角色**（本波实际只有 protocol 一次完整成功交付）。
- 并行会话（TUI 波、wave-37）共享工作区造成 2 次 git stash 事故、2 次 50x 交叉干扰、多次瞬时编译红——
  「共享工作区 + 多会话」必须配套**会话间通报协议**（本波靠收据 mtime 人工对账，成本高）。

## 2. 门禁穿透与误杀率

- 红相分权有效：8 卡全部有 SUT 原生断言红相，零假测试；L2-AT 独立核验在实现修完后仍抓到 2 处真实漏网
  （数字紧邻字母、IPv6 host:port）——对抗层价值再次实证。
- 误杀 1 起：c141_8 测试自身期望与 PlanStore 冻结语义矛盾（测试内部矛盾，非实现缺陷）——Lead 修测试并留档。
- 机器门禁盲区：50x 统计验收无法区分「已修复」与「未复现」，必须以根因证据（503 归属路径、单时钟采样）闭环；
  TTFT 竞态在 3 套 50x 中仅 1 次复现，靠数学不变式分析定位而非采样。
- PA-140 的 Windows verify 红被正确归因为 main 预存（对照 run 39103198486），避免误打回。

## 3. 分工契约与隔离有效性

- write_scopes 分文件声明 + 同文件双角色串行（test 先冻结、executor 后改生产区）执行良好，零写域事故。
- 例外：Lead 直接修改了 2 处测试（c141_8 期望、2 处 predicate）——均为裁决性修正且留痕，符合「裁决归 Lead」
  但提示**验收测试的修正权归属需在矩阵中显式预授权**，否则边界模糊。
- subagent 池承接实施时，交接成本高（前任半成品需考古）；改进：teammate 崩溃后应立即落盘 WIP 状态到
  `.dev-team/`（本波靠 git diff 考古）。

## 4. 元协议迭代建议

1. dev-team skill：为「常驻 teammate 不稳定」环境补一条降级 SOP——teammate 连续 2 次失败即切换 subagent 池，
   并要求每次交付把「改动文件+命令+exit code」写进 `.dev-team/evidence/` 而非只在消息里。
2. 共享工作区多会话：建议在 01_TASK_BOARD 顶部加「当前在飞会话」登记区（会话名+写域+预期时长），
   stash/50x 类长操作前先查登记。
3. 统计型验收（N 轮连跑）必须配「根因证据」条款：50/50 绿只是必要条件，失败样本的根因闭环才是充分条件。
4. L2-AT 在实现完成后仍应执行一轮（本波抓到 2 处漏网证明绿相后对抗不可省）。
