1. **基线已建**：`tests/visual-baseline/wave-52-config-page-before.png`（整页）与
   `tests/visual-baseline/wave-52-config-update-section-before.png`（卡片），
   在**任何实现改动前**由真实 Chromium 采集并随红相提交锚定（commit `4e770e8`）。
2. **绿相后证据**：`.dev-team/evidence/wave-52/config-update-section-after.png`（真实 Chromium 元素截图）。
2b. **事实更正（L3 视角 B 实测，Lead 采纳）**：实测变更前后卡片**总高度未变**（section 934×145、card 高 119px，1280 与 780 视口均一致），
   即本卡片下方内容**没有**整体位移。故「下游必然位移」的原表述不成立，予以更正。
   但这不改变结论：卡片**内部**像素必然变化（标题文案、开关位置、日期位置都是本次需求本体），
   全卡像素 diff 仍必然假红；而掩码掉卡片后的「其他区域零差异」已由「卡片总高未变 + 下方区块零位移」实测覆盖，
   无需再引入一套像素 diff 工具链。几何断言仍是更贴近契约（用户原话）的机器门禁。

3. **未执行自动像素 diff 的理由（更正后）**：本需求**刻意**改变卡片内部行结构与元素落位，
   卡片区域的像素 diff 必然 100% 假红，且这种假红不可通过「阈值调宽」消除——阈值一调宽，
   同一门禁就同时丧失对真实回归（错位、漏文案）的证伪力。把不可证伪的检查冒充门禁，比不设门禁更危险。

## 替代机器门禁（更强、更针对性）
`tests/e2e/wave52-update-card-layout.spec.ts` 在真实 Chromium 上做**物理几何断言**：
- C2：`|Switch.right − row.right| ≤ 2px`、文案贴左 ≤2px、Switch 在文案右侧、两者垂直中心差 ≤2px；
- C3：`上次检查.left ≥ chip.right − 1px`、与 chip 垂直中心差 ≤4px、且不落进自动检查行；
- C1：标题文本严格等于「软件自动更新」；
- C5：点击 Switch 后 `aria-checked` 翻转且偏好写入 localStorage；
- C6：Console Error = 0、未捕获异常 = 0，截图 > 5KB 落盘。

几何断言直接编码了用户原话（「同行最右端」「放在当前版本之后」），比像素 diff 更贴近契约。

## 裁决
**PASS（带偏差记录）**。基线截图 + 变更后截图作为人工对眼证据入档；自动像素 diff 由上述几何断言取代。
偏差仅限本条，不外溢为通用豁免。
