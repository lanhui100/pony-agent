## 4. 元协议迭代建议

1. **A 级任务也强制一次计划审查（低成本档）**：至少要求契约表每行承载列为一条可执行命令，禁止"既有测试 + grep 复核"
   这类非机器表述（本次 C6 即因此空心）。
2. **日志/输出类变更必须冻结"探针口径"**：契约须写明验收 grep 子串与作用面（log-scoped / source-scoped），
   并禁止新增行复用该子串；本次那条 BLOCKING 可被此模板直接前置拦截。
3. **可测性前置**：契约若要求"某外部输出不刷屏"，计划期就必须回答"用什么缝断言"；缝不存在时要么扩契约
   （引入注入点）要么显式降级为 review 项，不允许实施后才发现只能断言返回值。
4. **门禁收据须自带构建新鲜度证明**（承接 B071）：报告 `test result` 前先确认本次真的 `Compiling` 而非 `Fresh`，
   共享 target 的多 lane 场景下应默认用独立 `--target-dir` 复跑关键门禁。
5. **审查 JSON 增补 `round` / `supersedes` 字段**：本次 R1/R2 审查靠文件名区分轮次，无法机械判定
   "BLOCKING 是否已被后续轮次关闭"。
