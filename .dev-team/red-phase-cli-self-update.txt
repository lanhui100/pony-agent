## 六、覆盖缺口与口径说明（诚实申报）
1. **B 组落点**：`run_update_action` 是 bin 内私有函数，且 updater.rs 冻结 API 不含任何网络入口
   （下载编排标为「内部」，未冻结签名）⇒ 集成/对抗用例只能放在 bin 目标，运行方式：
   `cargo test -p pony-agent-core --bin pony cli_self_update`。`--lib` 门禁**看不到** B 组。
2. **发现流程（C4-1~3，releases 列表 → 取第一个含清单的 release）未覆盖**：逃生舱
   `PONY_UPDATE_MANIFEST_URL` 按契约跳过发现；冻结 API 无 release 列表入口。
3. **错误变体/消息级断言不可达**：CLI 路径只返回退出码且无法在进程内捕获 stdout/stderr，
   故 B 组以「C2 退出码 + 文件系统不变量」为断言面；
   `UpdateError::user_message()` 的消息内容（如 `sudo`/`PONY_UPDATE_INSTALL_PATH` 出路、
   「另一个 pony update 正在运行」）与「重定向错误串含 host / 不允许」只能在 lib 层断言，
   当前无冻结入口 ⇒ 登记为缺口。
4. **TooLarge 无专属退出码**：契约 C2 只定义 1/2/3/4 的语义分桶，TooLarge 归桶未明示，
   故第 25 条只锁「退出码非 0 + 绝不落盘 + 无残留」三条硬不变量（不放宽核心安全不变量）。
5. **Windows 平台**：自更新在 Windows 不支持（C6-6），B 组以 `#[cfg(unix)]` 编译期裁剪，
   非运行期 skip；`UnsupportedPlatform` 的 Windows 引导文案（改桌面安装包）当前无冻结可测入口 ⇒ 缺口。
6. **并发双实例（C7「两个实例同时 create_new，必有一个失败」）**：本波以「预置他人 lock ⇒
   退出码 4 且不删他人 lock」覆盖该不变量（第 22 条）；真并发双实例需两个进程各自注入 env，
   进程内测试无法稳定复现，登记为缺口。
7. **真实 GitHub 冒烟（C7 端到端第 2 条）属绿相/preprod**，不在红相范围。

## 七、清理保证
# 所有用例的临时目录 = std::env::temp_dir()/pony-update-test-<pid>-<seq>-<label>，
# 由 TempDir 的 Drop 整目录删除；只读目录用例另带 RestorePerms Drop 守卫恢复 0o755。
# env 注入由 EnvGuard 串行化（进程级 Mutex）并在 Drop 逐项还原（含 panic 路径）。
# mock HTTP 服务由 MockServer 的 Drop 置 shutdown 后 join，无遗留线程/端口。

# ═══════════════════════════════════════════════════════════════════════════
# AMEND（第二轮 · L3-B 变异反馈）：收紧超限用例的错误码区分力
# ═══════════════════════════════════════════════════════════════════════════
# 背景：L3-B 变异实测 —— 删除 updater.rs 两处 `MAX_ARTIFACT_BYTES` 判断后
#       `update_rejects_oversized_artifact_without_writing` 仍绿（超限被后续 size 校验路径兜住），
#       即该用例对「超限」分支零区分力；契约 C7 要求超限 ⇒ TooLarge。
# 改动范围：**只改这一条用例**（tui.rs cli_self_update_tests，净 +51/-4），其余 15 条未动。
#   · 新增错误码级断言：`matches!(err, UpdateError::TooLarge(_))` + `err.code() == "too_large"`
#     + `err.exit_code() > 0`（契约 C1 真值方法；实测当前实现的 JSON 收据 error.code 逐字为
#     "too_large"，与 C1 一致）。
#   · 保留原有三条硬不变量：非零退出 / 绝不落盘 / 无 .new·.part·lock 残留。
#
# 为什么不是「解析 stdout 的单行 JSON」（实测依据，非折衷）：
#   libtest 用 thread-local 捕获**测试线程**的 stdout，`println!` 被吞进用例缓冲、不落 fd 1。
#   本轮实测：dup2(1 → 捕获文件) + 在子线程里执行 run_update_action(..., json=true) 之后，
#   捕获文件仍为空串（`实际 stdout=""`），说明门禁命令下无法从 stdout 取 JSON。
#   故改用 CLI 内部**同一个入口** `run_self_update(&UpdateOptions{..})` 取得 `UpdateError` 本体：
#   `run_update_action` 的 JSON 收据就是 `error.code()` 的序列化结果 ⇒ 断言面等价，且不依赖
#   `--nocapture`（依赖 `--nocapture` 的用例在给定门禁命令下会假失败）。
#
# 变异静态推理（**未做经验变异**：`crates/pony-agent-core/src/agent/updater.rs` 当前有 executor 的
# 未提交改动（+132/-19），按 Lead 指令不做就地变异，只回传静态推理）：
#   · 现路径：`plan.size (MAX_ARTIFACT_BYTES+1) > MAX_ARTIFACT_BYTES`（updater.rs:525）
#     ⇒ `Err(UpdateError::TooLarge(plan.size))` ⇒ code()=="too_large" ⇒ 本用例绿。
#   · 删除 :525 的预检（或连同 :1044 流式判断一起删）：mock 实际只发 ~90 字节脚本，
#     `written > MAX_ARTIFACT_BYTES` 与 `written > plan.size` 均不成立 ⇒ 落到
#     `written != plan.size` 分支（updater.rs:1060）返回 `UpdateError::Signature(...)`
#     ⇒ `matches!(TooLarge)` 为 false 且 `code()=="signature"` ⇒ **两条断言立即红**。
#     这正是 L3-B 观察到的「被 size 校验路径兜住」的同一分支，故本断言可杀死该变异。
#   · 残余局限（诚实登记）：若只删 :1044 的流式判断而保留 :525 预检，本用例仍绿 ——
#     该分支只有「实发流量超过 128MiB」才能触发，无法在测试里廉价造出；若需覆盖，建议
#     另立条「declared size 小于实际流量 ⇒ 早停」的用例（会走 TooLarge(written) 分支）。
