# 技能根 Watchdog 热刷新机制设计

Status: proposed
Date: 2026-11-12

## Context
当前技能热加载依赖「每轮重扫 + 差分通知」的重型机制，无法在技能文件变更后即时响应，且缺乏 watchdog 的 200ms 稳定窗口，容易造成资源抖动。

## Proposal
引入 `watchdog` 机制实现轻量化增量加载：
1. **监听层**：集成轻量级文件监听，监听技能根目录。
2. **去抖策略 (Debounce)**：对监听到的文件事件增加 200ms 稳定窗口，过滤瞬态写盘行为。
3. **分发面**：变更经既有 `delta_notice` 通道推送，触发局部刷新而非全量重扫。
4. **状态隔离**：热刷新通道确保在过渡中 KV-cache 基线一致。

## Alternatives considered
### 方案 A：维持现有的每轮轮询重扫机制
- **否决理由**：缺乏 200ms 去抖机制，频繁引发全量扫描，消耗大量 I/O 且无法在变更稳定后及时触发通知。
