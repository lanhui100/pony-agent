# Agent Note: Harness 可扩展性三层模型与不可替换内核架构

Status: implemented

## Problem

在引入扩展机制（MCP、插件、外部工具）时，若缺乏清晰的架构分层与信任边界，系统容易滑向两种极端：

1. **过度插件化导致内核失控**：若将整个 Agent 调度循环、会话事实日志与底层权限检查全部做成运行时可动态热替换插件，会导致系统丧失确定性、安全边界被穿透且调试复杂度急剧上升；
2. **硬编码静态分派导致无法扩展**：早期工具与扩展点通过静态 `match` 绑定，外部协议（MCP 等）返回的工具无法动态装载进治理管线；
3. **前缀缓存（KV Cache）抖动**：若扩展工具的装载时机和顺序不稳定，会导致轮次间模型前缀缓存大面积失效。

## Decision

1. **按信任边界划分的三层架构模型**：
   - **L0 核心内核（不可替换）**：包含 turn loop 调度循环、会话事件追加写日志、沙箱物理边界、LLM 协议适配与权限/审批真源，严格随 Rust 版本演进，禁止第三方运行时热替换；
   - **L1 编译期接缝（Trait 实现）**：工具、模型服务商、沙箱后端等抽象接口，通过实现标准 trait 接入，扩展无需修改内核分派硬编码；
   - **L2 进程外插件（协议隔离）**：MCP 服务器与独立插件宿主，通过标准 stdio JSON-RPC 2.0 接入。进程边界即物理信任边界。
2. **三条核心架构不变量**：
   - **单一真值（Single Truth）**：工具元数据与权限事实必须来自 descriptor 注册表，严禁通过字符串推导；
   - **前缀稳定（Cache Stability）**：会话内可见工具面必须保持排序与条目稳定，杜绝缓存击穿；
   - **失败闭合（Fail-Closed）**：未知扩展、越权请求或超时故障一律拒绝，并提供精准错误分类。
3. **历史溯源与接替**：
   - 本决策源自并完全接替历史决策 `docs/archive/decisions/0064-extensibility-three-layer-model.md`。

## Alternatives considered

- **全量动态共享库（dylib / wasm）进程内热加载**：
  允许插件以 `.so` 或 WASM 形式直接加载到核心进程内运行。
  *落选原因*：Rust 缺少稳定的 ABI，进程内挂载不可信代码容易导致主进程崩溃，破坏系统韧性；相比之下，进程外 stdio 隔离具备天然故障隔离与安全屏障。
- **全动态无边界插件化（Cordis 式微内核）**：
  将 turn loop 和权限检查全部抽象为可被运行期配置文件替换的插件。
  *落选原因*：破坏安全基石与单一真源原则，显著增加排障与审计成本。

## Consequences

- 确立了不可替换 L0 内核与安全红线；
- 为后续 MCP（ADR 0066）与插件宿主（ADR 0067）奠定了坚实的分层边界基础；
- 兼顾了生态灵活性与工业级运行稳定性。
