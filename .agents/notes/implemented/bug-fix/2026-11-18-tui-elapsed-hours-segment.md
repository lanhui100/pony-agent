# Agent Note: TUI 耗时显示补小时段（>60 分钟不再写「93分钟」）

Status: implemented

## Problem

TUI 状态行与轮末过程摘要共用 `format_elapsed_seconds`（`src/bin/tui/text.rs`），原实现只有两档：

```
< 60s        ⇒  "45秒"
>= 60s       ⇒  "1分5秒" / "93分钟"
```

分钟数**无上界**。长轮次实测 55~96 步、28~75 分钟（见 `.agents/notes/implemented/bug-fix/` 中
retry 相关记录），跨小时的一轮就会渲染成 `93分钟`、`125分钟`——用户必须自己做一次除法才能
判断「这轮到底跑了一小时还是两小时」，而这段耗时正是判断「要不要继续等」的唯一依据。

## Decision

`format_elapsed_seconds` 增补小时段，分档成为：

| 区间 | 输出 |
|---|---|
| `< 1分钟` | `45秒` |
| `< 1小时` | `1分5秒` / `59分钟` |
| `>= 1小时` | `1小时` / `1小时2分钟` / `1小时5秒` / `1小时1分1秒` |

细则：

1. **零值段省略**：`1小时0分0秒` 折叠为 `1小时`，`1小时2分0秒` 折叠为 `1小时2分钟`；
   只在末尾段非零时带秒（与既有「`1分钟` 而非 `1分0秒`」的省略口径一致）。
2. **单点实现**：状态行（`elapsed_label`）与轮末摘要（`settled_turn_summary`）都走同一函数，
   不在调用点各自拼串——避免两处口径漂移。
3. **桌面端不在本次范围**：`src/lib/runtime/status.ts` 的 `formatElapsedSeconds` 仍停在分钟级，
   其既有断言（`3600000 ⇒ "60分钟"`）保持原样；本条只改 TUI 口径，跨端统一另立议题。
4. **可机器验收**：`crates/pony-agent-core/tests/tui_acceptance.rs::test_elapsed_seconds_formatting`
   新增 6 条小时段断言（整点、时+分、时+秒、时+分+秒、`1小时33分钟`、`59分钟` 边界不外溢）。

## Alternatives considered

- **A. 改成 `1h33m` / `93:00` 这类紧凑写法**：落选。TUI 状态行既有单位是中文（`秒`/`分`），
  混入 `h/m` 会让同一行出现两套单位；`93:00` 还要用户判断哪边是分哪边是秒，比现状更差。
- **B. 超过 1 小时只显示小时+分钟，丢掉秒**：落选。秒段是「还在动」的活体证据——短轮次
  靠秒刷新判断没卡死；直接砍掉会让刚跨过 1 小时的轮次反而失去刷新观感。省略只发生在**零值**上。
- **C. 加「天」档**：落选。单轮次跨天是异常（provider 重试预算与轮次时限都在小时级），
  为不存在的区间造档位属于投机抽象；真出现时 `25小时` 仍可读。
- **D. 在调用点各自格式化（状态行一套、摘要一套）**：落选。同一量两处拼串必然漂移，
  且既有实现已经是单函数共用，拆开是倒退。
- **E. 顺带把桌面端 `formatElapsedSeconds` 一起改**：落选（本次）。桌面端改动会牵动
  `tests/runtime-status.test.ts` 的既有契约断言与状态栏动效宽度预算，属跨端口径统一议题，
  与「修 TUI 一处显示」不是同一闭包；混在一起会让本次 diff 的验证面失控。

## Consequences

- 状态行示例：`生成中  1小时2分7秒`；轮末摘要示例：`本轮完成 · 用时 1小时33分钟 · 工具 35 次`。
- `>= 1小时` 时字符串变长（最多 `X小时YY分ZZ秒`，约 12 列宽），状态行的宽度预算
  （`width - 16 - str_width(&elapsed)`）已按实际 `str_width` 计算，自动收窄状态词预算，无需额外改动。
- 无新增对外接口、网络 IO、线程或后台任务；`docs/observability.yaml` 归属不变。
- 无旧决策被取代：该函数自 Wave-13 起只有中文单位口径，本次是**补档**而非改口径。
