# 0069 TUI 初始化页品牌标走终端图形协议，字符画降级为回退

Status: proposed

## 背景

初始化页的品牌标由字符网格绘制。终端的物理分辨率是「1 个字符宽 × 半个字符高 = 1 个方形像素」，
填充式字符画在 20×16、28×22 乃至更大网格上都会留下按字符格走的阶梯锯齿；两轮加密网格（20×16 →
28×22，分辨率 ×1.4）仍被判定「粗糙不平滑」。矢量级平滑只有一条路：让终端自己渲染真实位图。

## 候选方案

- **A 继续加密字符网格**（40×32 甚至更大）。落选：锯齿按比例缩小但永不消除；标变大后正文区高度
  不足会挤掉命令引导块，短终端还会整体隐藏品牌画。
- **B 半透明边缘抗锯齿（覆盖率混色）**。落选：近黑画布（#12100e）上部分覆盖像素会混成棕橄榄色描边，
  实测观感比硬边更脏；覆盖率混入同色高光则会变成发光描边，同样不是平滑边缘。
- **C 手绘线条/文字标**（box-drawing / 大字标）。落选：丢失填充渐变质感；╱╲ 字形在等宽字体中
  逐格断开，实机呈虚线而非连续斜线。
- **D（采纳）终端图形协议 + 位图资产 + 字符画回退**：sixel / kitty / iTerm2 直接由终端渲染位图，
  边缘由终端的图像合成管线平滑；不支持时回退现有字符画。

## 决策

1. 引入 `ratatui-image 8.1`（依赖 `ratatui 0.29`，与本仓一致）与 `image 0.25`（仅 `png` feature）
   承载编码与终端能力探测。
2. 品牌标位图由 `scripts/generate-splash-logo.py` 生成：以 20×16 字符画掩码的像素并集为轮廓，
   Douglas-Peucker 简化为直线边（保留原设计折角与描边宽度），4× 超采样栅格化后按 OKLab 渐变填色，
   画布底色不透明。产物内嵌为 `crates/pony-agent-core/assets/splash-logo.png`（616×484）。
3. 启动时 `Picker::from_query_stdio()` 探测：仅当协议非 `Halfblocks` 且进程不在
   tmux / screen / zellij 内时启用图形路径；`Halfblocks` 即自绘半块字符，保留字符画以获得更可控的边缘。
4. 显式覆盖入口（测试与复用器用户）：
   - `PONY_TUI_SPLASH_IMAGE_PROTOCOL=kitty|sixel|iterm2|off`（强制协议 / 关停图形路径）
   - `PONY_TUI_SPLASH_FONT_PX=WxH`（强制路径的字符格像素尺寸，默认 8×16）
5. 图形路径下字符横幅只保留 28×11 占位空白，位图铺在同一矩形；信息列与引导块布局不变。

## 后果

- 支持图形协议的终端获得真正平滑的品牌标；复用器默认回退字符画（实测 tmux 内能力探测会误报，
  图片实际不显示导致品牌标消失，故默认关闭并留 env 强制入口）。
- 新增依赖与内嵌资产；位图必须与渐变/掩码同步再生（脚本已入库，文档标注再生方式）。
- 验证：单测覆盖资产解码与占位尺寸；pty 内分别强制 kitty / sixel 抓取 stdout，解出终端实际收到的
  224×176 位图（RGBA / sixel DCS 解码）作为物理回执；tmux 内验证字符画回退路径与布局不变。
