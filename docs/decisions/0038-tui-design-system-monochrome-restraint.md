# ADR 0038：TUI 设计系统——单色为骨、单一骨色强调、发丝线与 2 列沟槽

Status: implemented

## 背景

`pony` TUI（`crates/pony-agent-core/src/bin/tui.rs`）此前的界面是高饱和多色方案：蓝紫双色 Header 底色带、ASCII 大字 Logo、胶囊徽章（`" USER "` / `" ● 就绪 "`）、方框输入框、每类消息各用一种强调色。

具体问题：

1. **层级靠颜色而不是留白与字重**：USER 紫、助手蓝、工具青、状态绿/琥珀/红同屏竞争，长会话变成色块噪声；
2. **中英混排**：命令描述为中文，而 `USER` / `ready` / `Sessions` 为英文，同一屏两种语言；
3. **中文字符宽度未计入**：折行与滚动偏移按字符数估算，CJK 双宽字符导致折行错位、滚动抖动；
4. **终端恢复与诊断缺失**（已由 626f023 修复）：非 TTY 静默退出、退出不还原备屏；
5. **无输入光标**：只能尾部追加/退格，无法在句子里改字；无换行输入能力；
6. **每次事件循环 60fps 全屏重绘**，空闲时也持续重绘。

设计目标是「极简、克制、高级感」——即克制的单色体系、单一强调色、精确的排版节奏，而不是增加装饰。

## 候选方案

### 方案 A：继续加色 / 加渐变 / 加边框卡片

用更多颜色与描边卡片表达层级（多数商业 TUI 做法）。

否决：颜色越多，层级越依赖色相，长会话阅读疲劳；且与「克制」目标相反。

### 方案 B：纯 ANSI 自适应色（跟随用户主题配色）

只使用 `Color::Reset` / `DarkGray` 等 ANSI 槽位，完全交由终端主题决定。

否决：无法保证浅色主题下的对比度与品牌一致性；且无法表达「单一骨色强调」这一视觉签名。

### 方案 C（采纳）：固定暗色画布 + 单色文本层级 + 单一骨色强调 + 发丝线分区

- 画布 `#0d0e11`，表面 `#181a1f`，选中底 `#262930`；
- 文本四级：`INK #e8e5e0`（用户/标题）、`INK_SOFT #cbc8c3`（助手正文）、`MUTED #9a9da3`（可读次要信息）、`FAINT #70747c`（纯 chrome：短 id、提示符描述）；
- 单一强调色骨色 `#c6a77e`，只出现在三处：输入提示符/光标、角色标签 `pony`、列表选中竖条；
- 状态语义色仅三枚（成功 `#8cac89`、警告 `#c7b07e`、危险 `#c77f7d`），且成功色只给「当前」行，历史行一律压暗；
- 分区只用 1px 发丝线（`#30333a`）+ 2 列左右沟槽，禁止整块边框、禁止 Header 底色带；
- 选中态用「骨色竖条 + 极淡底（+6% 亮度）」，不用反白 (inverse)；
- Composer 整宽表面色带（SURFACE #181a1f 铺满终端宽），仅靠色块与正文分区、不画发丝线；输入区最小 3 行高（上限 6）；底栏不放快捷键提示（键位靠 --help 与空态引导），最底行只保留右侧状态词；
- 空态 init 头部：左侧 14×10 像素半块字符拼成的彩虹渐变马蹄铁徽记（暖→冷 7 停靠点插值），右侧垂直居中的信息列（`pony v<版本>` / 模型(提供商) / 工作区）；整块作为会话流首条内容随对话向上滚动，正文区 1/3 高度锚定；
- 交互：光标感知编辑（←→/Home/End/Delete/Ctrl+U/Ctrl+W/Ctrl+A/E）、换行（Alt+Enter / Ctrl+J / 行尾 `\`+Enter）、Ctrl+C 有草稿先清空、Esc 清空或中断、`↑↓` 选择菜单、上下文相关底栏提示；
- 事件驱动重绘：非流式时仅在事件到达或状态变更时重绘（空闲 CPU 归零）；流式时 120ms 节奏刷新动画与耗时。

## 权衡

- 固定暗色画布牺牲了「跟随浅色主题」，换取可验证的对比度与一致的品牌观感；代价可接受（终端 Agent 用户以暗色为主，且画布仅在 TUI 运行时生效）。
- 骨色强调色饱和度低，在部分低色深终端上会退化为浅灰；这是刻意的——强调靠位置（竖条/光标）而非色相。
- 中文界面语言与英文技术名词（`alt+enter`、模型 id）混排是刻意保留的：动作用中文，按键与标识符用 ASCII，避免误读。

## 后果

- 新增渲染层回归测试 `crates/pony-agent-core/tests/tui_render_layout.rs`：沟槽不越界、CJK 不溢出且真实折行、自动贴底、面板不遮挡 footer、极小终端降级、光标位置与状态同步、模态压暗后 footer 仍可见。
- 折行与滚动改为「按显示宽度预折行 + 行数即偏移」，CJK/emoji 不再错位；行首禁则（`，。、；：？！）》」』…`）在折行与模型自带换行两种路径上都做悬挂处理。
- 空态按正文区 1/3 高度锚定，命令列表直接复用 `AVAILABLE_COMMANDS`，与斜杠菜单永不漂移。
- 终端恢复、非 TTY 诊断、信号处理沿用 626f023 的实现，未回退。
