# Wave 5 稳定性与 UI/UX 任务 DAG 依赖梳理

## 1. 任务阵列与核心依赖

| 任务 ID | 领域 | 依赖 (blocked_by) | 说明 |
| :--- | :--- | :--- | :--- |
| **B088** | 稳定性 | - | 启动期 HostRead 超时，属于基础链路修复 |
| **B103** | 稳定性 | - | 队友 transient 5xx 挂死，影响后续 Agent Team 实施 |
| **B104** | 稳定性 | - | 限流重试机制，影响所有需要网络交互的实施 |
| **B093** | 稳定性 | B088 | Token Metrics 重建，需先保证基础链路稳定性 |

| **B105** | UI/UX | - | 任务卡片 UI 渲染，不依赖其他逻辑 |

## 2. DAG 拓扑分析与并行策略

*   **并行第一层 (Group 1 - 基础设施修复)**：B088, B103, B104 (互不干扰，正交性高)
*   **并行第二层 (Group 2 - 依赖修复与 UI 优化)**：B093 (依赖 B088), B098, B105
*   **优化策略**：将稳定性优先作为 Phase 1 处理，确保实施环境可信；UI/UX 可以在稳定性修复的间隙并行实施。

## 3. 测试用例红相预设计 (B088, B093, B103, B104, B098, B105)

| 任务 ID | 核心测试点 (L2-T) | 对抗破坏用例 (L2-AT) |
| :--- | :--- | :--- |
| **B088** | 宿主读取函数是否有超时退出 | 注入宿主读取极长延迟，观察 UI 是否有加载错误提示 |
| **B093** | 验证整轮耗时是否正确折叠 | 快速并发调用观察 Metrics 时间戳是否错乱 |

| **B104** | 验证 4s 恢复窗口的等待机制 | 注入限流错误并返回 4s 恢复时间，断言逻辑是否等待而非退出 |

| **B105** | 长文本任务卡片渲染 | 注入超长标题任务卡片，验证是否自动换行而非省略号 |
