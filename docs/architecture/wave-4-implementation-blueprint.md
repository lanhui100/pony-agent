# 波次 4 (Wave 4) 总体实施蓝图

本蓝图定义了 Pony Agent 在第四阶段的架构演进与技术实施方向，旨在通过标准化协议、可观测性提升与债务治理，增强系统的跨进程协同能力与运行稳定性。

## 1. 核心目标
- **标准化通信**：实现 ACP 服务端，提供标准 JSON-RPC 接口，支撑多宿主接入。
- **治理与债务闭环**：消除 `eprintln`，补齐技能债务的技术债与安全应答闭环。
- **架构一致性**：确立 ACP/SDK 的跨进程通信安全隔离方案。

## 2. 实施蓝图模块
| 模块 | 关键任务 | 状态 |
| :--- | :--- | :--- |
| **ACP (B084)** | JSON-RPC stdio 服务端、session 事件映射、权限审批回调 | 待实施 |

| **日志 (B087)** | 结构化日志迁移 (tracing/log)、死锁豁免清理 | 待实施 |
| **债务 (B075-B086)** | 预算边界修复、手势测试补齐、ADR 契约补齐、Headless 授权补齐 | 待实施 |

## 3. 总体流程 (DAG 拆解)

实施顺序依据强依赖与正交性：

1. **基础治理 (并行)**:
   - 技能债务治理 (B075, B076, B078, B080, B086)：作为 ACP 开发的安全与可靠性基石。
   - 结构化日志迁移 (B087)：提供基础观测手段。
2. **架构建设 (串行)**:
   - ACP 宿主协议实现 (B084)
   - 跨进程 SDK 开发 (B085)

## 4. 红相审计检查点规划
每一波次实施必须通过以下审计门禁：
- **可观测性审核**: `ponygo observe audit` 确认所有新增接口均在 `docs/observability.yaml` 登记。
- **协议一致性**: 对 ACP 通信帧序列进行对拍测试，确保 `SessionUpdate` 事件与 core 事件一一映射。
- **安全门禁**: Headless 审批默认 fail-closed，权限反向调用必须提供物理审计日志。
- **契约闭环**: 新增 ADR 必须在同次提交完成 `contracts/skill-manifest.v1.schema.json` 同步。
