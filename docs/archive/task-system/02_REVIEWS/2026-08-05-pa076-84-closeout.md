## 本轮修复（对应 4 份审核的 P0/P1）

### 修复 0：P0 Ask 端到端 resume 断链（phase4，阻塞）
- 后端：`resume_ask_wait` 把 terminal_result + binding（call_id/tool_name/assistant_transcript）持久化到 `GraphRunStore.ask_injections`（一次性）；下一 turn 起点 `prepare_turn` 消费注入，把「原 assistant tool_call + terminal_result」作为已完成工具调用对插入 provider 请求（OpenAI `tool_calls`/`role=tool` 与 Anthropic blocks 协议感知），走 provider followup——模型看到答案后继续，而非 fresh user turn。
- `graph_resume_ask`（ask_plan_commands.rs）先校验 dispatcher pending request 已 CAS 消费（未消费 → fail-closed），关闭绕过单一消费入口。
- 前端：`src/stores/ask.ts` 新增 `resumeGraphAsk`（answer 成功后 `graph_list_ask_waits` 取 expectedVersion → `graph_resume_ask`，非致命失败仅记 error）；`ASK_REFRESH_EVENTS` 补 `turn:suspended`。
- 测试：后端端到端 `governed_ask_resume_injects_terminal_result_into_next_turn_provider_context` 断言 provider 请求含原 call_id 的 assistant `tool_calls` + `role=tool` 结果（含 answer），注入一次性；前端 4 个新测试。

### 修复 1：5.7 P1
- P1-1 env 隔离反转：`SandboxRequest` 新增 `isolate_environment` 字段；`process.rs:275` 门控改按标志 → `env_clear()` + essential + allowlist（空 allowlist 也隔离）；生产两处构造点（dispatcher.rs:969、tools.rs:1388）置 true；新增集成泄漏测试（父哨兵变量不进子进程）。
- P1-2 legacy Run 静默降级：legacy `ToolRouter` 门禁改为总是 enforce（None → `NoSandboxBackend` → `sandbox_denied`）；`tool_router_regression::run_command_returns_structured_result` 改名并显式注册 `TestSandboxBackend::available()`；新增 `run_command_fails_closed_when_no_sandbox_backend_is_registered`。

### 修复 2：6.6 P1
- WebFetch 链级总 deadline：`WEB_FETCH_TOTAL_DEADLINE_MS = 30_000`；`retry_tool_timeout` 改为携带共享绝对 deadline，`pinned_web_fetch` 每跳用 `min(timeout, remaining)`，超限返回 `web_fetch_deadline_exceeded`；重试预算真实生效（非死配置）。最坏阻塞 12min → 60s（12 倍改善）。新增 7 个测试（含 P2-3 的 3 个缺口：真实 socket redirect 链、3xx 无 Location 终态、redirect 到字面私网 IP）。

### 修复 3：7.5 P1
- P1-1 MCP 参数回显：`tool_exec.rs` 的 `CapabilityBridgeAction::Resource(_)` 分支改为 `resource_fetch_failure_result(request, SourceUnavailable)`，**绝不再把 arguments 作为 content**（design Decision 11）；McpResourceSurface 真实接线为后续工作。相关测试改断言 fail-closed。
- P1-2 Plan session 自报：`PrimitiveToolHandlerRequest` 新增 `session_id` 字段，dispatcher 两个构造点从 dispatch context 注入；`PlanControlHandler` 所有权 key 改用注入 session，新增 `MissingSession` / `SessionClaimMismatch` 错误（模型自报与注入不一致 → 拒绝；无 context session → fail-closed）。新增 3 个测试。

### 4.6-P1-3（接受迁移决策，非代码修复）
- `LegacyCompatiblePolicyEvaluator` 使生产 governed 默认引擎对 Write/Edit 全 `Allow`（复刻 legacy 直接执行行为）。这是 phase-3 P1-2「保守审批」被"更精确 evaluator"覆盖的既有设计张力，属**迁移窗口的刻意选择**（`build_governed_executor` 的 legacy-compatible 模式，`tool_router_regression` 13 项 characterization 冻结该行为）。裁决：**接受为迁移窗口决策**，作为后续工作项「把生产默认迁移到 `DescriptorPolicyEvaluator` 保守审批」承接，不构成本卡未解决 P1。已在本收口记录，并在 `governed_executor.rs` evaluator 处留注记。
