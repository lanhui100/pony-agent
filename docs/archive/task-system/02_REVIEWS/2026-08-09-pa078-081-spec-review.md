三路在关键事实上高度收敛（均经代码验证）：

- `Path::starts_with` 在 Windows 上大小写敏感（本机实测）；lowercase 字符串比较会重新引入前缀混淆。
- 宿主无 `get_workspace_root`、无对话框/fs 插件；WebView `File` 无路径 → 外部文件导入必须宿主侧完成。
- `MAX_TURN_IMAGES = 3`（`runtime/mod.rs:244`）；spec 原"4 张上限"为虚构。
- 前端 `createSession()` 纯本地、`TurnInput` 无 `workspaceId`、无 `create_session` command → 需明确线上传输。
- `AttachmentAsset.relative_path` 相对 `attachment_root` 解析，后端仅注册图片 asset → doc/text 不能声称进入该生命周期。
- 激活 workspace 被后端 command 与前端 localStorage 双持久化，需单一真相源。

## 采纳记录

### P0（全部采纳）

- A1（C-1/R-8/R-9/T-3）：PA-078 外部文件导入改为宿主侧——新增 `import_attachment { name, bytes, mime } -> { path }` + `get_workspace_root`；前端不做磁盘 IO；浏览器模式一律外部 + 仅内存引用（`path=null`）。
- A2（C-2/R-11/T-12）：PA-078 文档路由拆分——text 可提取格式内容注入（≤64 KiB 截断标注），二进制文档（pdf/docx/pptx/xlsx）引用附着（path+mime，不注入），模型走 `workspace_read_document`；spec 注册表为规范表，design 逐字复用。
- A3（T-1/C-8/R-1）：PA-080 Windows 比较——删除"`Path::starts_with` 忽略大小写"错误论断；改为 Windows 组件级 ASCII 小写折叠比较（绝不整体字符串前缀）；spec 加"既放行 `c:\ws\file` ⊂ `C:\WS` 又拒绝 `c:\ws-10` ⊄ `C:\WS`"双断言。

### P1（全部采纳）

- B1（T-2/C-6/R-16）：`workspace_id` 传输通道 = `TurnInput.workspaceId`（前后端同步），首次持久化盖章（None→默认）。
- B2（C-4/T-7/R-C-1）：激活 workspace 单一真相源 = 前端 localStorage；PA-079 移除 `workspace_activate`。
- B3（C-11/R-10/T-10）：图片上限 3（对齐 `MAX_TURN_IMAGES`），删除虚构"4 张"。
- B4（T-13/R-2/C-16）：写新文件复用 `prepare_workspace_file_path` 语义（最近存在祖先 canonicalize + 后缀组件校验）；受控 tmp 懒 `create_dir_all`；补"全新嵌套目录/后缀 `..`"场景。
- B5（R-4/C-18）：`authorize_path` scope 本轮仅 `"read"`，`"read-write"` 显式拒绝。
- B6（C-3）：AC#4 收窄到图片；doc/text 为引用附着（payload 经 workspace 路径解析，不注册 asset）。
- B7（C-9/R-C-3/T-9）：审批重发流明确（`requires_authorization` → permission event → `authorize_path` → 重发；本轮不接 Ask）；统一 `{ code, message }` 错误信封 + 各拒绝场景断言 code。
- B8（T-8）：`classify_path` 可注入 canonicalizer；hermetic fake resolver 测符号链接逃逸 + `#[cfg(unix)]`/junction canary。
- B9（C-5/T-16）：默认 id 保留字 `"default"`（豁免 `ws-<slug>`），常量共享 + 跨端断言。
- B10（T-6/C-12/R-21）：PA-081 AC 语义改写"切换激活不隐藏其他组"；瞬态"新对话"条目 `workspaceId = activeWorkspaceId ?? "default"`。
- B11（C-7）：`classify_path` 调用时按会话 `workspace_id` 经注册表解析 root（per-turn context），不依赖构造时固定 root。

第二轮新增发现均已采纳并修订：

- P1：`import_attachment` 增加 `workspaceId` 参数，宿主按会话 workspace 解析导入目标（spec 场景改为 `<session.workspace_root>/.tmp/imports/`）。

- P2：孤儿 `workspace_id` 路径解析策略——读回退默认 root 带告警、写 fail-closed。

- P2：`AuthorizeStore` RwLock 登记 lock-ordering.md；卷根授权测试补入对抗矩阵。
- P2：Windows 仅折叠 ASCII 的已接受限制记录（非 ASCII 大小写误拒为安全方向保守）。
