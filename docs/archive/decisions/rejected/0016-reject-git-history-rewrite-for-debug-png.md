# 0016 否决改写 Git 历史以清除已提交调试截图

Status: rejected — 历史改写成本与风险远高于一张调试截图的收益，且违反「审慎选择 PR 历史、禁 force 改写」的建军原则；除非未来出现真实的安全或合规泄漏需求方可重议。

## 背景

Wave 3 简化审计（2026-08-28）发现 `tmp-tauri-webview.png` 与 `tmp-tauri-webview-9224.png` 被误提交进 Git 历史（调试期 webview 截图，全库零引用）。二者已通过 `git rm` 从当前提交移除，但仍存在于历史提交中。

## 提案

使用 `git filter-repo` / `git filter-branch` 改写历史，从所有历史提交中彻底清除这两个文件。

## 备选方案

- **改写历史清除**：历史上永久消失。代价：重写全部历史提交哈希；违反「审慎选择 PR 历史、禁 force 改写」原则；并行会话与现有克隆的引用全部失配；过滤器本身引入新错误的可能。
- **`git rm` 仅移除现状（采用）**：文件从当前提交消失，历史完整保留。代价：历史中仍留着两张调试截图，体积影响可忽略。
- **不处理**：与采用项结果几乎相同（文件未被引用），但会留下"误提交截图是被接受的常态"的错误暗示。

## 护栏价值

本记录用于终止任何"历史洁癖清理"的重新提议——改写历史是诱人、常见、且几乎总是错误的选择。仅在以下条件**同时**成立时才允许重议：

1. 截图内容构成真实的安全或合规泄漏（而非"看起来不专业"）；
2. 仓库即将切换远端或存档，历史稳定性义务随之解除。
