# 0030 对话框面板内聚 Ask 提问交互优化

Status: implemented

## 候选方案

### 方案 A：消息流底部独立卡片面板（存量 AskPanel）
- **描述**：在消息列表末尾独立挂载带有醒目边框和告警底色的 AskPanel 卡片，包含独立输入框与操作按钮。
- **落选原因**：造成严重的界面撕裂感，屏幕上同时出现两个输入框导致用户认知混乱；过重的黄色边框与操作栏打破极简对话氛围。

### 方案 B：阻塞式模态弹窗（Modal Dialog / Drawer）
- **描述**：通过全局弹窗强制打断当前操作，要求用户回答后才能关闭。
- **落选原因**：遮挡聊天历史与上下文线索，打断沉浸感，在紧凑桌面端体验过于笨重。

### 方案 C：对话框输入面板直接内聚（选定）
- **描述**：
  1. 彻底移除消息流底部的独立 Ask 卡片，由底部的对话框面板（`WorkspaceComposer`）直接承载提问交互；
  2. 处于待提问状态时，隐藏原有消息输入框与下方 action 工具栏（模型、附件、权限、思考等）；
  3. 呈现极简设计：问题标题清晰显示；有选项时按 1、2、3 垂直排列，最后一项为用户可输入的自定义选项；无选项时呈现极简 textarea；
  4. 严格执行无边框规范，纯通过字体、字色与背景色建立轻盈视觉层级；
  5. 确认操作完全复用对话框原生的极简圆形发送按钮（及 Enter 快捷键）。
- **选定原因**：无缝融入输入流，消除多输入框认知负担；视觉极简清爽，键盘与点击操作高度连贯。

## 背景
Pony Agent 原有的 Ask（待确认交互）机制由 `AskPanel` 承载，该组件作为独立黄色卡片挂载于消息流和输入框之间。这种实现导致用户同时面对独立提问卡片与底部的对话框输入框，且下方工具栏与当前提问无关却持续可见，界面杂乱。

## 决策
1. **输入区域单一职责接管**：
   - 当检测到当前会话存在待处理的 Ask（`PendingAsk`）时，`WorkspaceComposer` 自动切换为 Ask 提问模式。
   - 隐藏常规 Draft 输入框与下方 Action 工具栏。
2. **结构化垂直排布与自由输入**：
   - 存在选项时：垂直排列序号项（1..N），前 N-1 项为预设选项，最后一项为可编辑的自定义输入项。
   - 预设首项推荐：第一条预设选项自动标注醒目暖色“推荐”徽章（`bg-amber-500/15 text-amber-800`）。
   - 弱显示辅助注释：每个选项下方渲染弱显示简明注释（`text-stone-400 text-[11px]`），预设项支持结构化解析及优雅回退语义，自定义项提示输入专属方案。
   - 无选项时：渲染极简无边框 `textarea`。
3. **极简无边框视觉**：
   - 消除所有卡片外边框与输入框边框（`border-none` / `border-0`），严禁任何 `border-*` 描边。
   - 通过字体粗细、字色对比和轻柔背景色区隔选中态与 hover 态。
4. **原生发送键与快捷键复用**：
   - 废除冗余的“回答/确认”按钮，直接复用原对话框发送按钮。
   - 支持回车键（Enter）确认提交当前选定项或输入内容。
5. **双通道 Trace 诊断沉淀**：
   - 提问面板如果应答或取消失败，除记录至前端环形缓冲区 Diagnostic Flight Recorder 外，同步沉淀至当前轮次的 `turnTraceHistory` 及 `TraceTimeline`，确保全链路可追溯。

## 影响
- `HomeWorkspace.vue` 消息流中不再渲染独立的 `<AskPanel />`。
- `WorkspaceComposer.vue` 新增 Ask 交互模式状态分支与提问提交事件处理。
- 所有原有的 Ask 提问/应答核心协议（compare-and-swap CAS 版本控制、`askStore`）保持不变，后端通过 `Option<u64>` 确保版本兼容。
